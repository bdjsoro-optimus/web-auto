## 사용 원칙

1. 본 catalog는 자식1.md §9 (친화적 추측-확인 패턴)에서 호출.

## 8 도메인 키워드 catalog

### 1. 수강권 / 구독권 / 멤버십

**일상 단어 예시**: "8회권", "12회권", "무제한권", "월 구독", "회원권", "패스", "이용권"

**암묵 결정 (5건)**:
- 만료 기간 — 90일? 60일? 180일? 무제한?
- 양도 가능 여부 — 다른 회원에게 넘길 수 있나
- 동결(holding) 가능 여부 — 부상·여행 시 일시 정지
- 잔여 처리 — 만료 시 잔여 회차 자동 소멸 vs 환불 vs 이월
- 환불 정책 — 부분 사용 후 환불 시 정산 방식 (정가 차감 vs 비례 환불)

**일상 단어 묻기 예시**:
- "8회권 같은 거 사면, 며칠 안에 다 써야 되나요? 90일 같은 기간 정해두실 거예요?"
- "회원이 다쳐서 한 달 못 오면, 그 기간만큼 멈췄다가 다시 쓰게 해드리나요?"
- "기간 지났는데 회차 남으면, 그냥 사라지게 할까요? 아니면 환불해드리나요?"

---

### 2. 결제

**일상 단어 예시**: "카드", "계좌이체", "간편결제", "카카오페이", "정기결제", "월 자동", "세금계산서", "영수증"

**암묵 결정 (5건)**:
- 환불 정책 — 7일 vs 14일? 부분 환불 시 비율?
- 결제 실패 처리 — 자동 재시도 횟수·간격
- 재시도 정책 — 카드 한도 초과·잔액 부족 시 익일 재시도? 즉시 알림?
- 세금계산서 발행 — 사업자만? 개인도 가능? 자동 vs 요청 시
- 정기결제 vs 일회성 — 멤버십 갱신은 자동 빌링키? 매번 동의?

**일상 단어 묻기 예시**:
- "환불은 며칠 안이면 가능하다고 정해두실 거예요? 7일이나 14일 같이요."
- "카드 결제 실패하면 — 자동으로 다시 시도할까요? 아니면 회원분께 바로 알려드릴까요?"
- "세금계산서는 사업자 회원분만 끊어드리나요? 개인분도 요청하면 발행해드리나요?"

---

### 3. 예약

**일상 단어 예시**: "예약", "신청", "수업 잡기", "노쇼", "안 옴", "취소"

**암묵 결정 (5건)**:
- 노쇼 정책 — 자동 차감? 경고 N회 후 차감? 면제?
- 이중 예약 방지 — 같은 시간 다른 수업 동시 예약 허용?
- 취소 마감 시간 — 24h 전? 1h 전? 그 후엔 불가능?
- 취소 시 차감 복원 — 마감 전 취소면 회차 복원, 그 후엔?
- 대기열 알고리즘 — 선착순? 우선권자 먼저?

**일상 단어 묻기 예시**:
- "회원이 예약해놓고 안 오면 — 그 회차 그냥 차감하시나요? 아니면 몇 번까진 봐드려요?"
- "수업 시작 1시간 전에 취소하면 — 회차 돌려드리나요? 그 시간 지나면 어떻게 하실래요?"

---

### 4. 정원 / capacity

**일상 단어 예시**: "정원", "최대 인원", "8명", "만석", "대기"

**암묵 결정 (4건)**:
- 만석 시 대기열 — 대기 가능? 즉시 마감?
- 우선권자 — VIP·장기 회원 우선 자리 잡기?
- 자동 승계 — 누가 취소하면 대기자 1번이 자동 들어가나? 알림 후 수동 확인?
- 정원 변경 정책 — 강사·룸별로 정원 다르게 설정?

**일상 단어 묻기 예시**:
- "한 수업에 몇 명까지 받으세요? 8명? 6명?"
- "꽉 찼을 때 대기 걸어두실래요? 누가 취소하면 자동으로 대기자분이 들어가는 식으로요."

---

### 5. 회원 · 사용자

**일상 단어 예시**: "회원 가입", "탈퇴", "재가입", "휴면", "강제 탈퇴", "신규 가입"

**암묵 결정 (5건)**:
- 가입 절차 — 카카오 OAuth만? 이메일 가입도?
- 탈퇴 시 데이터 처리 — 즉시 삭제? 30일 보관 후?
- 재가입 — 같은 번호로 재가입 가능? 이전 기록 복원?
- 휴면 회원 — 6개월·1년 미접속 시 자동 휴면? 알림 후 휴면?
- 강제 탈퇴 — 약관 위반 시 사유 기록·재가입 차단?

**일상 단어 묻기 예시**:
- "회원이 탈퇴 누르면 — 그 즉시 다 지워드릴까요? 30일은 보관했다가 지울까요?"
- "1년 동안 안 오시는 회원분은 — 자동으로 쉬는 회원으로 바꿀까요?"

---

### 6. 강사 · 직원

**일상 단어 예시**: "강사", "선생님", "시급", "정산", "급여", "단가"

**암묵 결정 (4건)**:
- 시급 변경 정책 — 소급 적용 vs 분리 적용 (변경 이전 수업은 옛 단가)
- 정산 주기 — 월 1회? 격주? 매주?
- 정산 기준일 — 매월 말일? 매월 1일? 수업 완료일?
- 강사 본인 일정 수정 권한 — 본인 수업만? 전체 일정?

**일상 단어 묻기 예시**:
- "강사 시급이 중간에 오르면 — 그달 이미 한 수업도 새 단가로 쳐드려요? 아니면 오른 날부터 적용?"
- "강사 정산은 매월 1일에 한 번 정리하실래요? 격주로 하실래요?"

---

### 7. 알림 · 통신

**일상 단어 예시**: "알림", "카톡", "문자", "이메일", "리마인더", "안내"

**암묵 결정 (4건)**:
- 발송 실패 폴백 — 카톡 실패 시 SMS? 이메일? 폴백 안 함?
- 재시도 정책 — 즉시 재발송? 5분 후? 횟수 제한?
- 우선순위 — 결제 영수증 vs 예약 리마인더 vs 마케팅 동시일 때
- 발송 시간대 — 22시 이후 발송 차단? 새벽 발송 금지?

**일상 단어 묻기 예시**:
- "카톡으로 알림 보낼 때 — 카톡 실패하면 문자로라도 자동으로 다시 보내드릴까요?"
- "밤늦게 알림 가면 회원분이 불편해하실 수 있는데 — 22시 넘으면 다음 날 아침에 보낼까요?"

---

### 8. 세션 · 예약 시간

**일상 단어 예시**: "수업 시간", "오후 7시", "리마인더", "24시간 전", "시간대"

**암묵 결정 (4건)**:
- 정확 시점 — 수업 시작 시각 기준? 종료 시각? 입장 시각?
- 시간대 — KST 고정? 회원별 timezone 지원?
- 24h 리마인드 정확성 — 정확히 24h 전? 전날 9시 일괄?
- 시간 변경 정책 — 강사 일정 변경 시 회원에게 알림 + 자동 재예약 옵션?

**일상 단어 묻기 예시**:
- "수업 24시간 전에 알림 보낼 때 — 정확히 24시간 전이 좋으세요? 아니면 전날 아침 9시 같이 한꺼번에 보낼까요?"
- "강사가 일정 바꾸면 — 회원분께 자동으로 알리고 다른 시간 골라 달라고 할까요?"

## 자식1 §9 호출 흐름 (L3 catalog 적용 가이드)

자식1이 사용자 인터뷰 도중 본 catalog를 호출하는 정해진 흐름:

### 단계

1. **사용자 자유 기술 수신** — Q1·Q2 답변 또는 [?LATER] 처리 중 들어온 텍스트.

2. **키워드 추출** — 본 catalog의 8 도메인 "일상 단어 예시" 와 매칭.
   - 예: "수강권 12회 팔아요" → 키워드 "수강권" 매칭 (도메인 1)
   - 예: "회원 80명 예약 받음" → 키워드 "회원"·"예약" 매칭 (도메인 5·3)

3. **catalog 매칭 → 암묵 결정 묻기** — 매칭된 도메인의 "암묵 결정" 항목을 1개씩 추측-확인.
   - "일상 단어 묻기 예시" 그대로 또는 사용자 발언 인용해서 자연스럽게 변형.
   - 한 번에 한 항목만 (§9 원칙).

4. **답변 기록** — 14섹션 매핑 표의 해당 행에 답변 반영.
   - 답변 모호 시 [?LATER:항목명] 마커 삽입 (§8 3단계로 위임).

### 적용 범위

- §8 1단계 핵심 5문항 답변 시점부터 항상 catalog 활성.
- 14섹션 완벽 루프 사이클마다 새 키워드 등장 시 재매칭.
- [?LATER] 1개씩 처리 시에도 본 catalog 참조.

### 안 하는 것

- 키워드 미매칭 시 catalog 항목 강제 묻기 X (의뢰인 도메인 아닌데 묻기 금지).
- 한 번에 catalog 8 도메인 다 묻기 X (사이클 당 매칭된 도메인만, 항목 1개씩).
- 기술 용어 그대로 사용 X — "noshow policy" → "안 오시면 어떻게 하실래요?"

## 026번 §Q1 8건 매핑 검증

본 catalog가 026번 §Q1 누락 정책 8건을 모두 커버하는지 매핑:

| # | 026 §Q1 정책 누락 | 매핑된 도메인·암묵 결정 |
|---|---|---|
| 1 | 수강권 가격 | 도메인 1 (가격은 catalog 외 — 사용자 직접 답 영역, 자유 기술 또는 [?LATER]) |
| 2 | 만료 기간 | 도메인 1 → 만료 기간 |
| 3 | 수업 정원 | 도메인 4 → 정원 변경 정책 |
| 4 | 무제한권 잔여 정책 | 도메인 1 → 잔여 처리 |
| 5 | 환불 정책 (24h? 7일?) | 도메인 2 → 환불 정책 + 도메인 3 → 취소 마감 시간 |
| 6 | 노쇼 정책 | 도메인 3 → 노쇼 정책 |
| 7 | 강사 시급 변경 정책 | 도메인 6 → 시급 변경 정책 |
| 8 | 세션권 만료 잔여 처리 | 도메인 1 → 잔여 처리 (수강권과 동일 매핑) |

→ 8건 중 7건 catalog 직접 매핑. 1건(수강권 가격)은 사용자 직접 답 영역 — Q14 negative list 또는 자유 기술에서 수렴.
